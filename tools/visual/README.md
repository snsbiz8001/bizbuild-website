# 시각 회귀 테스트

CSS나 마크업을 정리할 때, **화면이 정말 그대로인지 픽셀 단위로 확인**하는 도구다.

눈으로 보는 확인은 전체의 0.001% 수준 차이를 놓친다. 실제로 이 도구를 만든 계기가
`#hero .hero-note` 규칙을 "값이 같은 중복"으로 잘못 판단해 지웠다가, 글자색이
`#B8C2D4` → `#D8DEE8` 로 밝아진 것을 292픽셀 차이로 잡아낸 일이다.

## 처음 한 번만

```bash
cd tools/visual
npm run setup          # 의존성 + 크롬 설치 (약 150MB, 5분)
```

## 사용법

```bash
cd tools/visual

node shot.js before              # 고치기 전 촬영
#   ... CSS 수정 ...
node shot.js after               # 고친 후 촬영
node compare.js before after     # 픽셀 단위 대조
```

여러 페이지를 한 번에:

```bash
node shot.js before index,stage1,stage2,stage3
```

차이가 났을 때 **어디가** 달라졌는지 찾기:

```bash
node locate.js before after index-w1440.png
#   → 차이 구간의 y 좌표를 알려주고, 해당 부분을 잘라 shots/crop/ 에 저장
```

배포 후 실제 사이트 점검:

```bash
node verify-live.js              # CTA 태깅·Clarity·Meta 픽셀 동작 확인
```

## 판정 기준

**픽셀이 100% 동일할 때만 통과**로 본다. 1픽셀이라도 다르면 실패다.
높이가 달라진 경우는 즉시 실패 — 레이아웃이 밀렸다는 뜻이다.

의도적으로 화면을 바꾼 경우에는 당연히 차이가 난다. 그때는 차이 이미지를 열어
**의도한 곳만** 바뀌었는지 확인하면 된다.

## 촬영 조건

9개 화면폭에서 전체 페이지를 찍는다. `@media` 경계(600·768·900px)를
앞뒤로 끼워 넣어 경계에서만 나는 버그를 잡는다.

```
1440  1024  901  900  768  601  600  390  360
            └┬┘        └┬─────┘
         900px 경계   768·600px 경계
```

결과가 실행마다 흔들리지 않도록 통제하는 것들:

- **웹폰트를 `.fontcache/` 에 캐시** — 구글 폰트를 매번 네트워크로 받으면
  응답 지연에 따라 줄바꿈이 달라져 페이지 높이가 수십 px 흔들린다
- **애니메이션·트랜지션 정지**, `.fade-up` 을 전부 표시 상태로 고정
- **이미지 로딩·디코딩 완료까지 대기**
- **Clarity·Meta 픽셀 차단** — 화면에는 영향 없고 타이밍만 흔든다

서버는 `shot.js` 가 알아서 띄우고 내린다. 따로 실행할 필요 없다.

## 의심스러우면 두 번 찍어라

혹시 결과가 미심쩍으면, **같은 코드로 두 번 찍어 서로 비교**해 본다.

```bash
node shot.js chk1
node shot.js chk2
node compare.js chk1 chk2      # 여기서 차이가 나면 도구 문제
```

여기서 완전 동일이 나와야 비교 결과를 믿을 수 있다.
