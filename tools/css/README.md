# CSS 죽은 코드 검사

CSS 를 고치다 보면 **적용된 적이 없는 코드**가 쌓인다. 화면에는 아무 표시가
나지 않으므로 눈으로는 찾을 수 없다. 이 도구가 기계적으로 찾아준다.

## 사용법

```bash
cd tools/css

node check.js              # 저장소의 모든 html 검사
node check.js index.html   # 특정 파일만
```

설치할 것이 없다. Node 만 있으면 된다.

문제가 있으면 종료 코드 1 로 끝난다(중복 선택자만 있으면 0).

## 무엇을 찾는가

### 1. 항상 덮이는 선언

뒤에 오는 규칙에 무조건 져서 **한 번도 적용된 적이 없는** 선언이다.

```css
.footer-brand .brand-logo{margin-bottom:16px;}   /* 이 줄은 무의미하다 */
...14줄 뒤...
.footer-brand .brand-logo{display:flex;margin-bottom:24px;}
```

특히 놓치기 쉬운 것 — **미디어쿼리는 우선순위를 올려주지 않는다.**
선택자가 같으면 순서로만 결정되므로, `@media` 안의 선언이 파일 뒤쪽의
기본 규칙에 지는 일이 생긴다. 실제로 네 페이지 모두 이 형태로
`.footer-bottom p{font-size:13px}` 가 죽어 있었다.

```css
@media(max-width:600px){
  .footer-bottom p{font-size:13px;}    /* 모바일에서 작게 하려던 의도 */
}
.footer-bottom p{font-size:14px;}      /* 뒤에 있어서 항상 이긴다 */
```

### 2. 대상 없는 규칙

HTML 에도 JS 에도 그 클래스/ID 가 없는 규칙이다. 섹션을 지우거나 마크업을
새로 짰을 때 CSS 만 남아 생긴다.

`<script>` 안의 문자열까지 훑어서, `classList.add('scrolled')` 처럼 **JS 가
나중에 붙이는 클래스는 살아있는 것으로 본다.** 이걸 안 하면 `nav.scrolled`
같은 정상 코드를 지워 기능이 깨진다.

그룹 선택자 안에 살아있는 이름과 죽은 이름이 섞여 있으면 `그룹 안 일부만 죽음`
으로 표시한다. 이때는 규칙 전체가 아니라 **그 이름만** 빼야 한다.

### 3. 중복 선택자

같은 선택자가 여러 곳에 흩어진 경우다. 죽은 코드는 아니지만,
한 곳만 고치고 "왜 화면이 안 바뀌지?" 하게 만드는 원인이다.
합칠지는 사람이 판단한다 — 의도적으로 묶어둔 블록일 수도 있다.

## 오탐에 대해

처음 만들 때 `max-width` 만 이해하도록 짰다가, `@media(min-width:601px)` 와
`@media(prefers-reduced-motion:reduce)` 를 기본 규칙으로 잘못 읽어
`judgment.html` 의 **정상 코드 2건을 죽었다고 보고**했다.

그래서 지금은 **포함 관계를 증명할 수 있을 때만** 죽었다고 판정한다.

| 뒤 규칙의 범위 | 앞 규칙을 죽이는가 |
|---|---|
| 기본 규칙(미디어쿼리 없음) | 죽인다 — 모든 상황에 적용되므로 |
| 앞 규칙과 조건이 완전히 같음 | 죽인다 |
| `max-width:B` vs 앞의 `max-width:A` | `B >= A` 일 때만 죽인다 |
| 그 밖(`min-width`·`prefers-*` 등) | **판정하지 않는다** |

즉 판정을 못 하는 경우는 조용히 넘어간다. 놓치는 편이 멀쩡한 코드를
지우라고 하는 것보다 낫기 때문이다.

`!important` 가 붙은 선언은 순서를 이기므로 죽음 판정에서 제외한다.
